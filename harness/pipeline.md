# Pipeline (R3)

입력: 유저스토리 번호 1개 (harness-goal.md)

## 단계

| 단계 | story-work 단계 | 입력 | 출력 |
|---|---|---|---|
| S1 리서치 | 1 수집 + 2 분석 | 유저스토리 번호 | 레퍼런스 5–10장 (스크린샷 + UIBowl URL + 메모), 반영할 점 3–5개 |
| S2 설계 | 3 화면설계서 | S1 출력 + PRD 해당 기능(F-xx) | 화면설계서 md 2–3개 |
| S3 키스크린 | 4 키스크린 → 5 사람 승인 | S2 출력 | Figma `01_Keyscreen` 프레임 2–3개 + 승인 기록 |
| S4 본 디자인 + 검토 | 6 토큰·컴포넌트·화면 + 7 검토 | 승인된 키스크린 + DESIGN.md | `02_Tokens`·`03_Components`·`04_Screens` + 판정 리포트 |

진행 순서: S1 → S2 → S3 → [사람 승인] → S4 → 완료

## 되돌아가는 지점

| 발생 위치 | 조건 | 돌아갈 곳 |
|---|---|---|
| S3 승인 | 반려됨, 사유가 설계 | S2 |
| S3 승인 | 반려됨, 사유가 레퍼런스 부족 | S1 |
| S4 판정 | 위반 1건 이상 | S4 안에서 고친 뒤 다시 판정 |
| S4 판정 | 같은 위반이 3회 반복 | 멈추고 사람에게 알림 |
| S1–S2 | 되돌아가는 지점 없음 | 형식 체크만 한다 |

## 원칙
- 이전 단계의 결과물은 직접 고치지 않는다. 그 단계로 되돌아가서 다시 만든다.
- 사람 승인 없이 S4로 들어가지 않는다 (story-work "어기면 안 되는 것" 2번).
